Web Unlockerとは？Bright Dataの仕組み・使い方・料金と無料枠を解説

note公開済み開発・インフラ・データ 5,292字
#BrightData #WebUnlocker #スクレイピング

Web Unlockerは、アクセスを遮られやすい公開ページから情報を取得するAPIです。対象URLを渡すと、接続方法の選択やJavaScriptの描画などをBright Data側へ任せられます。

通常のプロキシやBrowser APIとの違いから、最初のリクエスト、料金、利用時の注意点まで順に紹介します。

Web Unlockerで任せられること

  • 提供元：Bright Data
  • 処理：接続選択・ブロック対応・描画
  • 入力：対象URLと認証情報
  • 出力：HTMLやJSONなど
  • 課金：成功リクエスト単位
  • 無料枠：対象製品共通で月5,000クレジット

Bright Dataに登録して無料クレジットを試す →

登録画面では、無料クレジットの対象製品とWeb Unlockerの開始条件を見られます。

Web Unlockerが自動化する処理

IPローテーション、ブロックに応じた再試行、JavaScriptの描画をBright Data側で処理します。利用者は主に取得先と出力形式を指定します。ただし、すべてのページを必ず取得できるわけではありません。

入力するものと受け取れるもの

取得したいURL、APIトークン、Web Unlocker用のZoneを指定します。処理が成功すると、HTMLやJSONなどの取得結果が返ります。

通常のプロキシ・Browser APIとの違い

使い分けの基準は、ページ取得に必要な操作と、自前で持つ処理の範囲です。URLを渡して内容を受け取るだけなら、Web Unlockerが候補になります。

通常のプロキシは取得処理を自分で組む

通常のプロキシでは、接続先やIPを細かく選べます。その一方で、再試行、ヘッダー、Cookie、ブラウザ実行は自分で組みます。

  • 自前処理：接続制御から失敗時の処理まで
  • 画面操作：別途ブラウザ環境が必要
  • 状態保持：Cookieやセッションを自分で管理
  • 課金単位：転送量またはIP数

既存の取得基盤があり、細かな制御を残したい場合に合う方式です。

Web Unlockerは1回のAPI呼び出しに処理をまとめる

Web Unlockerでは、対象URLを中心にリクエストを組み立てます。

  • 自前処理：対象URLと出力後の処理が中心
  • 画面操作：クリックや入力には不向き
  • 状態保持：長い画面遷移より単発取得向け
  • 課金単位：成功リクエスト

プロキシの選択や再試行を自前で保守したくない場合の選択肢です。

ログインやクリックが必要ならBrowser APIを検討する

ログイン後のページ移動やフォーム入力には、Browser APIが候補です。

  • 自前処理：画面操作の手順を記述
  • 画面操作：クリックや入力に対応
  • 状態保持：複数画面にまたがる処理を想定
  • 課金単位：データ転送量

ページ内で操作が必要かどうかを基準に、Web Unlockerと使い分けます。

Web Unlockerが取得結果を返す仕組み

対象URLを送ってから結果を受け取るまで、次の4段階で処理が進みます。

  1. 対象URLと認証情報を送る
  2. Bright Data側が接続方法を選ぶ
  3. 必要に応じて描画や再試行を行う
  4. 成功した取得結果を返す

対象URLと認証情報を送る

リクエストにはAPIトークンとZone名を使います。APIトークンはBearer認証で送り、共有するコードには実値を残しません。

接続・描画・再試行をBright Data側で処理する

送信後は、接続方法の選択、JavaScriptの描画、失敗時の再試行が行われます。

成功した取得結果を受け取る

処理が終わると、指定したページの内容が返ります。成功したリクエストが課金対象です。

HTTP応答だけでなく、返された本文まで見て取得の成否を判断します。

Bright Dataに登録して無料クレジットを試す →

登録後は、Web Unlocker用のZoneを作り、リクエストに使う認証情報を準備できます。

Bright Dataで最初の1件を取得する手順

最初は対象URLを1つに絞り、レスポンスの中身まで確認します。大量取得へ進む前に、設定と課金単位を切り分けておくためです。

  1. Bright Dataへ登録する
  2. Web Unlockerを選び、専用Zoneを作る
  3. APIトークンとZone名を控える
  4. 認証情報を環境変数へ保存する
  5. cURLで対象URLへリクエストする

Web Unlocker用のZoneを作る

管理画面の製品一覧からWeb Unlockerを選び、Zoneを作成します。既存のプロキシ用Zoneを、そのまま指定しないようにします。

日本語の公式サイトはありますが、管理画面全体の日本語対応範囲は明記されていません。画面では製品名とZone名を目印に設定を進めます。

APIトークンとZone名を確認する

APIトークンは認証に使い、Zone名で利用する設定を指定します。トークンは環境変数やシークレット管理へ保存します。

cURLで対象URLへリクエストする

実際に試すときは、次の環境変数とZone名、対象URLを自分の値に置き換えます。

curl https://api.brightdata.com/request \

-H "Authorization: Bearer $BRIGHT_DATA_API_TOKEN" \

-H "Content-Type: application/json" \

-d '{"zone":"YOUR_WEB_UNLOCKER_ZONE","url":"https://example.com","format":"raw"}'

レスポンスが返ったら、まず内容を確認します。保存や抽出はその後です。

Bright Dataに登録して無料クレジットを試す →

登録画面から、Web UnlockerのZone作成とAPIトークンの準備へ進めます。

取得結果とエラーを確認する

初回テストでは、次の3点を見ます。

  • 指定したHTML・JSONなどの形式で返ったか
  • 対象ページの本文か、チャレンジ画面か
  • ダッシュボードの消費クレジットは想定どおりか

HTML・JSONなど必要な形式で返っているか見る

formatの指定とレスポンスが合っているかを照合します。抽出へ進む前に、必要な項目が本文に含まれることも確かめます。

本文ではなくチャレンジ画面が返っていないか見る

HTTPステータスだけでは、目的の本文かどうかを判断できません。ページタイトルや主要な要素を見て、チャレンジ画面ではないかを判別します。

失敗時は認証・Zone・対象URLから切り分ける

まずBearerトークン、Web Unlocker用Zone、対象URLの順に入力を見直します。入力に問題がなければ、レスポンス本文とダッシュボードの消費クレジットを照合します。

Web Unlockerの料金と無料クレジット

Web Unlockerには無料クレジット、従量課金、月額プランがあります。対象製品と消費単位は、それぞれ分けて確認します。

  • 無料クレジット：対象製品共通で月5,000
  • Pay as you go：$1.5／1,000成功リクエスト
  • Scale：$499／月、383,000リクエスト込み
  • Scale超過分：$1.3／1,000リクエスト
  • Enterprise：条件は個別相談

Pay as you goの1,000件は、1ドル=157円換算（執筆時点の目安。為替で変動）で約236円です。

月5,000無料クレジットの対象と数え方

新規アカウントには、対象製品で使える月5,000クレジットが付与されます。Web Unlockerは、1リクエストにつき1クレジットです。

対象製品で使うクレジットは共通のプールから消費され、毎月1日に5,000へ戻ります。未使用分は翌月へ繰り越されません。

Datacenter、ISP、Residential Proxiesは、この月額無料枠の対象外です。

少量ならPay as you goで始める

Pay as you goには月額の契約枠がなく、成功リクエスト単位で使います。1万件なら$15、10万件なら$150が目安になります。

利用量が読めるならScaleと比較する

Scaleは月$499で、383,000リクエストを含みます。超過分は1,000件あたり$1.3です。Pay as you goは、月約33.3万件でScaleの月額と並びます。これを超える見込みなら、Scaleとの料金差を比べます。

月額契約の料金は返金不可です。Enterpriseは個別に条件を相談します。

支払いはクレジットカードやPayPalなどに対応し、銀行送金は大口アカウント向けです。対応カードブランドにJCBの明記はありません。電子請求書・領収書は契約条件に含まれますが、日本の適格請求書発行事業者番号は案内されていません。税の扱いは税理士に確認してください。

Bright Dataに登録して無料クレジットを試す →

登録時に、月5,000クレジットの対象とリセット条件を見てから始められます。

Web Unlockerが向く場面・向かない場面

必要な操作と取得後の処理を切り分けるのが、Web Unlockerを選ぶときの判断基準です。

ブロック対応をまとめて任せたい取得に向く

公開ページを定期的に取得し、接続経路の調整や再試行までBright Dataへ任せたい場面に向いています。

  • 商品情報や公開データを一定間隔で取得する
  • JavaScriptで描画される公開ページを取得する
  • プロキシや再試行の保守範囲を減らす

取得後の抽出、整形、保存は利用者側で行います。

ログイン・クリック・長いセッションには向かない

ログイン後に複数画面を移動する処理には、Browser APIを含む別の方式が向いています。

  • ログイン状態を保ったまま操作する
  • ボタン操作やページ送りが必要になる
  • 人の画面操作に近い処理を続ける

画面操作が中心なら、Web Unlockerだけでは処理を組み立てられません。

利用規約・robots.txt・個人情報・アクセス負荷を確認する

Web Unlockerは取得を補助する製品であり、対象データの利用許可を与えるものではありません。対象サイトの利用規約とrobots.txtを読み、個人情報や著作物を含む取得範囲と頻度を決めます。

Web Unlockerでよくある質問

導入前に迷いやすい点を、3つに絞って回答します。

コードを書かずに使える？

APIを呼び出すための設定は必要です。少なくとも、認証情報、Zone名、対象URLをリクエストへ入れます。

完全なノーコード製品ではありません。まずcURLで最初の1件を取得し、動作を確かめてから利用中の言語へ組み込みます。

管理画面やサポートは日本語に対応している？

日本語の公式サイトは用意されています。ただし、管理画面全体の日本語表示範囲は公開情報から判断できません。

日本市場向けの支援は案内されていますが、日本語の有人対応範囲も明記されていません。契約前に問い合わせて確認します。

Web UnlockerでもKYCは必要？

KYCの条件は、利用する製品や権限で異なります。Residential Networkの条件が、Web Unlocker全体に共通するわけではありません。

登録画面に表示される対象条件を読み、追加確認を求められた場合は案内に沿って提出します。

まとめ：自前保守を減らしたい取得から無料クレジットで確認する

最後に、月間件数と契約条件を照らし合わせます。

Web Unlockerを選ぶ前の4項目

  • 月約33.3万件未満：Pay as you goの金額を先に試算
  • 月約33.3万件以上：Scale（月383,000件込み）と比較
  • 支払い条件：カード・PayPal・大口向け銀行送金から選択
  • 契約条件：月額料金は返金不可、対象データの規約は別途確認

まず1件の取得結果と課金単位を確かめる

最初はリクエストを1件だけ送り、レスポンス本文と消費クレジットを確認します。必要な結果を得られたら、月間件数を見積もります。
